## Core and package boundary

The final runtime is `25bf231`; declaration packaging is qualified at `99c7e1e`.
All 65 JavaScript files remain byte-identical after the declaration changes.
The final candidate tarball has SHA-256
`4286068c10ae4b9d0164ebe0f04854d695cbe96397659894cb8ac007ef9e5cbf`.
This is a local candidate, not an npm publication or version change.

Formatting, lint/typecheck, build, public type examples, publint, 254 unit tests,
55 repository checks, and 1,555 jsdom tests pass. Chromium, Firefox, and WebKit
each pass 53 core browser tests; seeds `0..99` pass 201 lifecycle cases. The same
18 packed consumer contracts pass against both the candidate and published 0.2.4.
Normalized reachable types remain unchanged. Public declaration output retains
symbol names, class metadata, and JSDoc as well as callable contracts.

The [performance evidence](../benchmarks/core-architecture-25bf231.json)
contains three sequential captures per revision, all sample-quality fields,
the original failed captures, and the resolution and navigation controls.
All 21 guardrails qualify: maximum slowdowns are 1.91% against the preceding
stage and 4.77% against the initial baseline. Monaco's entry is 224,987 bytes
against its unchanged 225,000-byte limit. These measurements make no general
optimization claim.

## Sibling and generated applications

The [machine-readable consumer evidence](./core-consolidation-qualification.json)
records all 13 sibling commits, unchanged lockfiles, original core versions,
candidate digests, dependency-tree replacements, fixture adaptations, and results.
Every original sibling checkout remains unchanged. Every sibling and generated
application passes its final typecheck.

Charts, CLI, examples, i18n, logos, Lucide, Monaco, server, themes, Vite, Destroyer,
and website pass their complete `check` or `acceptance` command. The UI package
passes build, lint, types, unit, integrity, jsdom, publint, and packed consumer
checks. Its browser suite passes 1,473 cases and retains one existing virtualized
Menubar failure in all three engines (`2` instead of `42`). Published 0.2.4
reproduces that same failure. No assertion is skipped or weakened.

Some isolated fixtures require mechanical setup for this comparison: npm 12's
pack JSON object form is normalized, nested consumer installs use the candidate
archive, and website expectations are derived from published 0.2.4 instead of
its pinned 0.2.3. Website declaration source formatting is normalized before
deriving its reference snapshot; names, documentation, members, and signatures
remain checked. All fixture edits are restored after validation.

SPA, SSR, and SSG applications generated by packed CLI 0.2.3 pass their complete
checks. Browser verification covers SPA navigation and controlled input, SSR
HTML plus hydrated counter updates, and generated SSG HTML plus hydrated counter
updates. SPA and SSG use production preview; SSR has a client/server production
build and uses the development server for the serving check. SSG sitemap, robots,
and manifest artifacts are verified. No deployment is part of this qualification.
