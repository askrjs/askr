## Auth contraction and reviewed feature additions

The published Auth 0.4.2 baseline has 93 named/path pairs. Ten implementation helper removals plus six browser-session removals leave **77 retained baseline pairs**. The server-session engine and four native presets add **24 pairs**, giving **101 final pairs**. The develop-only two-name Auth0 SPA SDK adapter is also withdrawn but was never in the published 93-pair baseline. It cannot be counted as a published reduction.

[#64](https://github.com/askrjs/askr-auth/issues/64) explicitly selects server-held sessions for SSR and SPA, retires the browser session/SDK paths, and requires Auth0, Apple, Microsoft and Google presets. Its [merged contract](https://github.com/askrjs/askr-auth/blob/2bc51fa288505ecbd5f5afcddec2a490cc45a5a3/docs/server-session-contract.md) establishes the shared server engine, durable store, cancellation and typed failure boundaries. The 24 additions provide these application contracts:

| Names                                                                          | Supported need                                                                                                            |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| `createProviderSession`, `ProviderSession`, `ProviderSessionOptions`           | Create/configure/inject the server-owned login, callback, resolve, token, logout, finalize and close lifecycle.           |
| `createOidcProvider`, `OidcProviderOptions`, `ProviderDefinition`              | Configure a generic standards-compatible provider and pass a branded definition to the common engine.                     |
| `ProviderClientAuthentication`, `ProviderCapabilities`                         | Configure confidential-client secret rotation and explicit renewal, consent, logout, revocation and resource policy.      |
| `ProviderSessionStore`, `ProviderSessionRecord`                                | Implement durable cancellation-aware atomic revisioned storage and retirement tombstones.                                 |
| `ProviderLoginRequest`, `ProviderLogoutRequest`, `ProviderTokenRequest`        | Type route inputs for provider selection, return destination, resource/scopes and cancellation.                           |
| `ProviderSessionError`, `ProviderSessionErrorCode`, `InteractionRequiredError` | Distinguish safe operational failure categories and interactive login/consent without exposing provider response details. |
| `createAuth0Provider`, `Auth0ProviderOptions`                                  | Select and configure native Auth0 protocol/resource policy.                                                               |
| `createMicrosoftProvider`, `MicrosoftProviderOptions`                          | Select and configure tenant-bound Microsoft protocol and Graph consent policy.                                            |
| `createGoogleProvider`, `GoogleProviderOptions`                                | Select and configure Google identity and separately consented API resources.                                              |
| `createAppleProvider`, `AppleProviderOptions`                                  | Select and configure Apple form-post, signed-client authentication and account-check policy.                              |

Auth is not a very small package. Its **101 > 93** net surface does not meet #745's literal smaller-surface alternative, and the accepted #64 feature scope does not silently waive that condition. The review must explicitly reconcile the two requirements: approve measuring the 77-pair retained baseline separately from the 24 reviewed feature additions, or require further supported cuts before acceptance. No compatibility shim or unsupported new symbol should be retained to influence that decision. Keep #745 open until the independent surface review and explicit coordinator disposition are recorded.

Collapsing a named request/configuration type into `Parameters`, indexed access or `ReturnType` can remove an annotation name while leaving behavior reachable. That is a possible design change, not proof that its consumer ergonomics are redundant. The final review must assess each proposed cut against the typed Server/store/provider callers and packed TS6/TS7 checks; deleting nine names solely to make 101 smaller than 93 is not acceptance evidence.

## Executed bounded caller search

The [exact-source caller sweep](./0.5.0-api-caller-sweep.json) uses Core's locked `@typescript/typescript6@6.0.2` wrapper, which delegates to locked TypeScript 6.0.3, to inspect 3,169 source/Markdown files and 13,173 import/reference checks across the frozen 18 package sources, Examples `a10fe69f56357c1891711aa2b51d6593e8db74d0`, and Website `c7b17435665293d510742529fe2797cba5c6d280`. This durable rerun reproduces the original sweep's counts and dispositions. The receipt records both package and actual compiler versions and hashes the implementation. It includes imports, exports, dynamic literal modules, namespace members, Markdown code fences and generated import/export strings. No executable stale caller was found. All 219 literal retired references have associated `@ts-expect-error` rejection assertions. Seven computed placeholder references are separately disposed from their bounded driver/provider selectors or positive catalog test generation.

This search excludes prose and arbitrary computed module/name expressions; it is not a consumer typecheck. Later integrated source commits, Destroyer's independently owned application state, and regenerated application output require their own appropriate search/build evidence. Existing complete18 producer packed/type/archive receipts support the frozen source only. The final integrated consumer and hosted gates below remain open.

### Reproduce and verify the evidence

The committed [runner](../../tests/checks/api-acceptance/sweep.ts) uses the
[inventory](./0.5.0-api-inventory.json) and
[computed-reference dispositions](./0.5.0-api-caller-dispositions.json), without
untracked proposals or temporary scripts. Install Core's locked dependencies
with `npm ci`. Supply a directory containing the 20 sibling Git repositories
named in the receipt, with their recorded commits available locally. Source is
read from immutable Git blobs; working-copy edits and current branch names do
not affect this frozen search. No repositories are fetched or changed.

From the Core checkout:

```sh
npm run check:api-acceptance -- --workspace-root /path/to/sibling-checkouts
```

The default check verifies all recorded source trees, package and lockfile
hashes, baseline manifests, export-map decisions, and pinned evidence documents.
It hashes the compiler implementation, Core lockfile, all three runner modules,
inventory, dispositions, and each source file selection. It checks the exact
seven computed findings against their source hashes and rejects unmatched,
duplicate or stale allowances. Any executable stale finding fails the command.
The regenerated receipt must equal the committed receipt in every field.

To also independently enumerate the 6,835 final named/path pairs from the exact
candidate archives, supply the directory containing package artifact folders
such as `askr/askrjs-askr-0.5.0.tgz`:

```sh
npm run check:api-acceptance -- --workspace-root /path/to/sibling-checkouts --archives-root /path/to/candidate/artifacts
```

This verifies all 18 archive SHA512s and 2,198 declaration SHA256s before compiler
enumeration. It compares the complete exported tuple set, including wildcard
expansions, with the committed inventory. Archives are extracted only into an
owned temporary directory that is removed after the check. This enumeration
does not replace the existing packed TS6/TS7 consumer and runtime gates. Run the
existing packed consumer matrix with both locked compilers:

```sh
npm run test:installed
```

After reviewing an intentional source, tool or disposition change, regenerate
the receipt by adding `--write` to the same command. Re-run the default check and
review the receipt diff. `npm run test:checks -- tests/checks/api-acceptance/sweep.test.ts`
exercises stale caller detection, generator and Markdown cases, exact allowance
matching, pinned source reads, changed hashes, archive export drift and stale
receipts without requiring sibling repositories in CI. It also checks that the
committed receipt matches the local runner, compiler, lockfile and input hashes.
