## Auth contraction and reviewed feature additions

The published Auth 0.4.2 baseline has 93 named/path pairs. Ten implementation helper removals plus six browser-session removals leave **77 retained baseline pairs**. Merged [Auth #82](https://github.com/askrjs/askr-auth/pull/82) retains **15 additions**, giving **92 final pairs (33 values, 59 types)**. The earlier 101-pair candidate is superseded. The develop-only SDK adapter and nine withdrawn type names were never in the published 93-pair baseline, so neither is counted among the 16 published-baseline removals.

The contraction retains all required server-held Auth0, Apple, Microsoft and Google flows from [#64](https://github.com/askrjs/askr-auth/issues/64). It keeps the common provider/session engine, durable stores, cancellation/error contracts and all five factories. It removes these standalone annotation names while preserving exact contextual and derived shapes:

| Withdrawn name                                                                                      | Retained owner                                                                                                                                     |
| --------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ProviderLoginRequest`, `ProviderLogoutRequest`, `ProviderTokenRequest`                             | `Parameters<ProviderSession["login"]>[1]`, `NonNullable<Parameters<ProviderSession["logout"]>[1]>`, and `Parameters<ProviderSession["token"]>[2]`. |
| `ProviderCapabilities`, `ProviderClientAuthentication`                                              | `ProviderDefinition["capabilities"]` and `ProviderDefinition["clientAuthentication"]`.                                                             |
| `Auth0ProviderOptions`, `MicrosoftProviderOptions`, `GoogleProviderOptions`, `AppleProviderOptions` | `Parameters<typeof createProvider>[0]` for the matching retained preset factory.                                                                   |

Use the [exact merged migration](https://github.com/askrjs/askr-auth/blob/9f1ea8139e20387adde693922aa6feb1ec19d735/docs/0.5.0-api.md#method-and-factory-type-ownership) for complete types and examples. Packed TS6.0.2/TS7.0.2 tests reject all nine imports and verify derived request/configuration types, callback context, readonly fields, closed unions and factory branding. The full Auth gate passes 444 unit tests, nine browser cases and signed simulated-provider HTTP flows for all four presets. All 20 emitted runtime JavaScript files match the pre-contraction develop build byte for byte. The exact reviewed head `8b14a0a228e87e6ba5e29c205da4254226342b6f` passed [three OS CI](https://github.com/askrjs/askr-auth/actions/runs/38321824199) and [CodeQL](https://github.com/askrjs/askr-auth/actions/runs/38321822396); its source tree equals the merged commit's tree.

### Reproduce and verify the evidence

The committed [runner](../../tests/checks/api-acceptance/sweep.ts) uses the
[inventory](./0.5.0-api-inventory.json) and
[computed-reference dispositions](./0.5.0-api-caller-dispositions.json), without
untracked proposals or temporary scripts. Install Core's locked dependencies
with `npm ci`. Supply a directory containing the 20 sibling Git repositories
named in the receipt, with their recorded commits available locally. Source is
read from immutable Git blobs; working-copy edits and current branch names do
not affect this pinned search. No repositories are fetched or changed.

From the Core checkout:

```sh
npm run check:api-acceptance -- --workspace-root /path/to/sibling-checkouts
```

The default check verifies all recorded source trees, package and lockfile
hashes, baseline manifests, export-map decisions, and pinned evidence documents.
It hashes the compiler implementation, Core lockfile, all three runner modules,
inventory, dispositions, and each source file selection. It checks the exact
seven computed findings against their source hashes and rejects unmatched,
duplicate or stale allowances. Any executable stale finding fails the command.
The regenerated receipt must equal the committed receipt in every field.

To also independently enumerate the 6,826 named/path pairs from the exact
candidate archives, supply the directory containing package artifact folders
such as `askr/askrjs-askr-0.5.0.tgz`:

```sh
npm run check:api-acceptance -- --workspace-root /path/to/sibling-checkouts --archives-root /path/to/candidate/artifacts
```

This verifies all 18 archive SHA512s and 2,198 declaration SHA256s before compiler
enumeration. It compares the complete exported tuple set, including wildcard
expansions, with the committed inventory. Archives are extracted only into an
owned temporary directory that is removed after the check. This enumeration
does not replace the existing packed TS6/TS7 consumer and runtime gates. Run the
existing packed consumer matrix with both locked compilers:

```sh
npm run test:installed
```

After reviewing an intentional source, tool or disposition change, regenerate
the receipt by adding `--write` to the same command. Re-run the default check and
review the receipt diff. `npm run test:checks -- tests/checks/api-acceptance/sweep.test.ts`
exercises stale caller detection, generator and Markdown cases, exact allowance
matching, pinned source reads, changed hashes, archive export drift and stale
receipts without requiring sibling repositories in CI. It also checks that the
committed receipt matches the local runner, compiler, lockfile and input hashes.
