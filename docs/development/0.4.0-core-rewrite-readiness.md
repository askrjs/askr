# Askr 0.4.0 Core Rewrite Migration Map (Historical)

> **Archived snapshot.** This readiness map was prepared before the coordinated
> Askr 0.4.0 release. It records the migration surface and issue references at
> that time; it is not a current release checklist. The 0.4.0 line has since
> shipped. Use the package repositories and [Coordinated Release](./coordinated-release.md)
> for current compatibility and release state.

This page tracks consumer preparation for the Askr core rewrite across the
package repositories. It is a migration map, not a release authorization or a
claim that every package is ready to publish. Package code, tests, docs, and
release notes remain owned by each package repository.

## Core compatibility changes

The rewrite gives public exports one canonical entrypoint. Consumers need to
prepare for these changes before adopting the 0.4 line:

| Previous import                                                         | Canonical import or replacement                       |
| ----------------------------------------------------------------------- | ----------------------------------------------------- |
| `For`, `Show`, `Case`, `Match` and their prop types from `@askrjs/askr` | `@askrjs/askr/control`                                |
| Query functions and query types from `@askrjs/askr`                     | `@askrjs/askr/data`                                   |
| `getSignal` from `@askrjs/askr/resources`                               | `@askrjs/askr`                                        |
| `onRouteChange` from `@askrjs/askr/resources`                           | `@askrjs/askr/router`                                 |
| `resolveRequest`, `renderResolvedToStringSync` from `@askrjs/askr/ssr`  | Remove use; these are no longer public exports        |
| `debounce` from `@askrjs/askr/fx`                                       | `debounceEvent`                                       |
| `JSX` from a global namespace                                           | `import type { JSX } from '@askrjs/askr/jsx-runtime'` |
| Query fetcher `({ ...input, signal })` parameter                        | `(input, { signal })`                                 |

The CLI generator must also stop emitting the nonexistent
`@askrjs/askr/query` subpath. The server package should use the core route
matcher rather than maintain a second implementation.

## Qualification gates

- Close or explicitly resolve the migration issues listed above before the
  corresponding package release.
- Build and test against the 0.4 candidate, including generated applications
  and packed consumer declarations where the package publishes types.
- Confirm every package manifest, peer range, and lockfile resolves to the
  intended release wave. Do not merge a dependent package while its required
  version is unpublished and its CI cannot install that version.
- Update each package's changelog for user-visible breaking changes.
- Follow [Coordinated Release](./coordinated-release.md) for publish and merge
  ordering; this checklist does not change that process.
