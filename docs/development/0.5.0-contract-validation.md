# Public contract validation for 0.5.0

An absent export needs a diagnostic caused by that absence. The previous
`@ts-expect-error` assertions wrapped properties in `expectType<never>(...)`.
Restoring an export still produced an argument-type error, so the directive
consumed that error and the test passed. The same problem affected a removed
type used as the argument to that helper.

The public entrypoint fixture now reads missing value properties directly and
looks up missing types in their owning modules. Restoring either export leaves
an unused `@ts-expect-error`, which fails compilation. Two checks reuse the
actual fixture statements with both missing and restored virtual declarations.
Both fail against the previous assertions and pass with the corrected ones.
The ordinary installed-package test compiles those absence assertions with
both repository TypeScript compilers, printing each actual compiler version.

`matchRoute` and `resolveRouteRequest` are deliberate router contracts used by
Server and application tests. Their stale negative assertions are replaced by
positive calls that check their results. This verification change does not
alter the runtime exports, declarations, package map or versions. The complete
KEEP/REMOVE/MOVE review in [#746](https://github.com/askrjs/askr/issues/746)
remains open.

The root `createElement` export is required by the automatic JSX transform's
classic fallback when a `key` follows a spread. It must survive an API cut.
The packed fixture now typechecks that syntax under TypeScript 6 and 7 and
renders it through the installed runtime, asserting the attribute and content.
This complements the direct factory assertions in the existing JSX type suite.

Run `npm run test:checks`, `npm run test:types` and `npm run test:installed`.
`npm run check` includes those checks with the existing unit, DOM, browser,
declaration, lint, build and package-artifact gates. The complete 0.5.0 candidate
graph and maintainer review remain separate publication gates.
