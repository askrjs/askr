## Package and integration checks

- **Core and server.** The core 0.5.1 packed consumer verified rendered status and body through `createServerApp().fetch()`. A consumer installed with core 0.5.0 verified ordinary 200 and fallback 404 when the render result omitted status.
- **Core and i18n.** A clean consumer installed packed core and i18n plus jsdom. Running `node deferred-consumer.mjs` checked the immediate French render, interleaved French and English shells, reverse settlement order, translated patches and hydration with markup verification.
- **CLI, fetch and schema.** A clean consumer installed all three local tarballs. It ran the packed CLI twice for each inline and referenced model and compared the output trees byte for byte. TypeScript compiled positive and negative client calls. Executing both clients checked nested requests, successful responses and malformed 200 and 400 bodies.
- **PostgreSQL.** All 31 integration tests passed against separate target and scratch databases in a disposable local PostgreSQL cluster.
- **SSR benchmarks.** `npm run bench:tier1 -- ssr` passed all five cases and `npm run bench:tier2 -- ssr` passed all four.
- **Repository checks.** Core passed formatting, lint, types, build and its test suites. Server, ORM, CLI, fetch and i18n passed their repository checks. UI passed build, lint, types, unit, integrity, jsdom, package and browser checks across the runs. All 2,475 UI browser cases passed across Chromium, Firefox and WebKit. One Firefox menubar assertion timed out in the three-worker run and passed on its individual rerun. The expanded viewport regressions passed again in all three browsers.
